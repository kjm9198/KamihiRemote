# Kamihi Remote v0.4 Product Quality Milestone — Architectural Design Specification

## 1. Executive Summary & Root-Cause Hypotheses

### Root Causes of Current Physical Failures:
1. **Multi-Touch Finger Disappearance & Gesture Annihilation**:
   - In `GestureEngine.swift:ended`, when 3 fingers lift, capacitive screen touch release events arrive asynchronously (e.g. 3 -> 2 -> 1 -> 0 fingers over ~30ms). The moment finger count drops from 3 to 2, `ended` called `applyCount(2)`, which immediately demoted `mode` from `.threeFingerSwipe` to `.twoFingerCandidate`, wiping `startCentroid`, `swipeAxis`, and accumulated displacement. Thus, by the time the final finger lifted (`remaining == 0`), the gesture was evaluated as a single-finger tap or pointer mode.
   - In `TrackpadView.swift`, `event?.touches(for: self)` vs `event?.allTouches` was not consistently aggregating coalesced samples, leading to missing intermediate micro-movements during fast swipes.
2. **Visual Jumps / Identity Swapping**:
   - `TouchAnimationView.swift` rendered orbs using `ForEach(Array(points.enumerated()), id: \.offset)` with ID `finger-\(index)`. When finger #1 lifted while finger #2 stayed down, finger #2 became index `0`, causing SwiftUI to violently animate orb #0 from point A to point B instead of cleanly fading orb #0 and keeping orb #1 stationary.
3. **Scroll Momentum Physics Jitter & Frame-Rate Dependency**:
   - `ScrollGestureEngine.swift` applied `vx *= effectiveScrollDecay` once per CADisplayLink frame without multiplying by actual elapsed time `dt`. This caused 120Hz ProMotion displays to stop scrolling twice as fast as 60Hz displays.
   - Velocity was estimated using single-frame alpha decay `(dx / dt) * 0.35`. A small decel on the last touch frame wiped out high-speed flick momentum.
4. **Security & Session Authentication Gap**:
   - Realtime MOVE UDP traffic relied on `encodeV1` (pairing token plaintext) or `encodeV2` (plaintext session string). While `SessionCrypto.swift` existed, live UDP packets were not encrypted/authenticated with AES-GCM sealed boxes, leaving them vulnerable to injection and replay.

## 2. Multi-Touch & Gesture Architecture

### Complete Touch Ingestion Pipeline:
```
UITouch (UIKit)
   │ (Captures touchesBegan/Moved/Ended/Cancelled + Coalesced touches)
   ▼
TrackpadUIView (maintains stable ObjectIdentifier -> Int dictionary for touch lifetime)
   │ (Preserves entire active touch set [FingerSample(id, point)])
   ▼
TouchInputEngine (Coordinates display link, debug overlays, and stats)
   │
   ▼
GestureEngine (State Machine with Invariant Protection)
   ├── Gesture Tracking Session (preserves max finger count & cumulative displacement across async lifts)
   ├── 1-Finger: Tap / Double-Tap / Drag / Pointer Acceleration
   ├── 2-Finger: Tap (Right-Click) / Mac-like Scroll / Pinch-to-Zoom
   ├── 3-Finger: Tap (Lookup/Middle-Click) / 4-Way Swipe (Mission Control, Exposé, Spaces)
   └── 4-Finger: 4-Way Swipe (Desktop Switch, Launchpad)
   │
   ├──► TouchAnimationState (stable [TouchAnimationFinger(id, point, phase)])
   │       └──► TouchAnimationView (Liquid Glass, Metaballs, Scroll Flow, Tap Ripples)
   │
   └──► RemoteCommand Stream
           ├── Realtime (UDP / AES-GCM Encrypted MOVE/SCROLL/CONTROLLER)
           └── Reliable (TCP / Bonjour / Pairing Handshake / App Catalog)
```

## 3. Frame-Rate Independent Scroll & Momentum Physics

Let $v(t)$ be the scroll velocity at time $t$. We model natural Mac friction via continuous exponential decay:
$$v(t + \Delta t) = v(t) \cdot e^{-\lambda \cdot \Delta t}$$
where $\lambda$ is the friction coefficient tuned for Mac-like feel ($\lambda \approx 3.2\text{ s}^{-1}$).
This guarantees mathematically identical deceleration whether sampled at 60Hz, 90Hz, or 120Hz.

### Robust Weighted Velocity Estimation:
Instead of a single noisy frame, we maintain a rolling timestamped sample buffer over the last $60\text{ ms}$:
$$v_{\text{release}} = \frac{\sum_{i=1}^{N} w_i \frac{\Delta x_i}{\Delta t_i}}{\sum_{i=1}^{N} w_i}, \quad w_i = e^{-\frac{t_{\text{now}} - t_i}{\tau}}$$

## 4. End-to-End Authenticated Session Architecture

1. **Pairing**:
   - Mac generates temporary 6-digit PIN + ECDH Curve25519 public key.
   - iPhone scans QR or inputs PIN, sends `.pairRequest(deviceID, name, iphonePubKey, pin)`.
   - Mac shows native dialog: "Allow iPhone [Name] to control this Mac?".
   - Upon approval, both sides derive shared session key via ECDH + HKDF(SHA-256) with ephemeral session ID. Key is stored securely in Keychain.
2. **Encrypted Realtime UDP Traffic (`K3`)**:
   - Packet format: `K3 <sessionID> <sequence: UInt64> <nonce: 12-bytes base64> <ciphertextAndTag: base64>`
   - Ciphertext contains encoded `RemoteCommand` wire payload.
   - Host `UDPServer` decrypts via AES-GCM with session key, verifies sequence number $> \text{lastSequence}$, and applies input. Replayed or forged packets are rejected with zero crash risk.
